### 2.6 Technical Approach

* **Module:** `src/boostgauge/skins/stingray.py`
* **Pattern:** Module-level Memoization / Pure Rendering
* **Key Decisions:** The rendering logic directly leverages `PIL.ImageDraw` by delegating to `visual_contract_render.py`. Caching is implemented via `functools.lru_cache(maxsize=16)`. Constants defined in the aesthetic render contract are hardcoded within this module and strictly kept internal.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Cache Scope | Instance cache vs. Module cache | Module cache | Avoids passing a cache instance around; ties cache lifecycle to the app process (session), satisfying #329 natively. |
| Verification Mechanism | Pixel diffing vs. Geometric predicates | Geometric predicates | Per strategy doc, tests must not rely on implicit auto-accepts but instead assert strict mathematical properties bound to the render contract. |

**Architectural Constraints:**
- Must exclusively use `PIL` for drawing; no `tkinter` components in the rendering or testing pipeline.
- Geometry and layout constants cannot leak out of the skin module.

## 3. Requirements

1. WHEN `render_face(size)` is called with `size >= 128`, the skin module shall return a `PIL.Image` of dimensions `size x size` containing every static element and no needles.
2. The system shall render the dial face (S1) as flat `#0A0A0C`, radius R = 0.40 x size, centre (0.5, 0.5) x size, with no gradients or reflections.
3. The system shall render the redline band (S2) in crimson `#AA0F19`, extending from inner 0.88 R to outer 1.00 R, spanning values 60-100 mapped via `angle = 225 - 2.7 * value`.
4. The system shall render major ticks (S3) in white `#FFFFFF`, exactly 11 total at values 0, 10, ... 100, length 0.10 R, width 0.025 R.
5. The system shall render minor ticks (S4) in white `#FFFFFF`, exactly 40 total (4 between each major pair), length 0.05 R, width 0.012 R.
6. The system shall render numerals (S5) in white `#FFFFFF` for values 0-100 step 10, with cap height 0.11 R, centered at 0.72 R from the pivot.
7. The system shall render the wordmark (S6) `BOOSTGAUGE` in white `#FFFFFF` with cap height 0.09 R, centered horizontally at 0.67 R below the pivot.
8. The system shall render the chrome housing (S7) as a square with chamfer radius 0.13 x size and environment-strip generation adhering to #328.
9. The system shall render exactly 2 screws (S8) at pivot + (-0.25 R, 0) and pivot + (0.25 R, 0), radius 0.020 R, flat `#1A1A1C`.
10. The system shall render a bezel seat (S9) forming an inner shadow on the transition annulus containing 1.01 R, leaving the dial face itself free of any shadow overlays.
11. WHEN the same `(size, skin)` is requested twice in one session, the system shall render the image only once and serve the cached instance on subsequent calls.
12. The application code shall obtain the face only through the skin module's public call; no dial geometry, color, or layout constant may exist outside the skin module.
13. WHEN the visual test tier runs with `--generate-baselines`, the run shall write the rendered face PNG into the run's artifacts directory AND print its path to stdout.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Combined Dynamic/Static Render | None | Recalculates static pixels on every tick; massive CPU overhead per issue #1 postmortem | **Rejected** |
| Cache in Application State | Clean dependency injection | Exposes cache mechanics to consumer | **Rejected** |
| Module-level Memoization | Zero API friction; strictly isolates the render logic | State resides globally in the module | **Selected** |

**Rationale:** The #329 caching mandate requires the rendering layer to abstract away the fact that it caches. `functools.lru_cache(maxsize=16)` is the lightest, most correct mechanism to enforce a session-scoped, bounded singleton cache without injecting state containers into the caller.
