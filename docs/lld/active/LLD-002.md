### 2.5 Logic Flow (Pseudocode)

```
1. Initialize TelltaleGroup using config values (short, medium, long, None).
2. On new SystemSnapshot:
   - Calculate normalized value.
   - For each telltale in group: update(timestamp, value).
3. On render refresh:
   - Collect current_peak() from the four telltales.
   - Call boostgauge.skins.stingray.render(value, telltales_list, size).
4. On context menu reset selection:
   - Call reset() on the corresponding Telltale instance (or all of them).
5. On hover:
   - Compute tooltip text using format_window_label and aesthetic color names.
   - Display tooltip.
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/gauge.py`
* **Pattern:** Dependency Injection / Pure Functions
* **Key Decisions:** The label formatting and tooltips are extracted into pure functions to allow `tkinter`-free unit testing (Option C testing strategy). The app acts strictly as an integration layer, routing `timestamp` and `value` downstream and delegating all drawing to `#332's` renderer.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Label formatting | In GUI layer, Pure function | Pure function | Enables unit testing covering all time unit branches without instantiating `tkinter.Tk()`. |

| Renderer interaction | Draw needles, Pass values | Pass values | Adheres to strict scope guard; passes a 4-slot array (with `None` passed through) to `stingray.render`. |

**Architectural Constraints:**
- Must never instantiate `tkinter.Tk()` in unit test suite.
- Must not implement peak-tracking algorithms.
- Must not implement needle rendering.

## 3. Requirements

1. The application shall instantiate four Telltale instances: three with durations read from telltale_windows.short, telltale_windows.medium, telltale_windows.long, and one with window None for all-time.
2. The application shall feed every collector sample to all four instances via Telltale.update(timestamp, value), each receiving the exact same timestamp and value per sample.
3. Every refresh shall pass all four current_peak() values to the renderer (boostgauge.skins.stingray.render) as the four-slot telltales argument, passing None through unfiltered.
4. The short-window menu entry shall call reset() on the short-window instance; the remaining three shall be untouched.
5. The medium-window menu entry shall call reset() on the medium-window instance; the remaining three shall be untouched.
6. The long-window menu entry shall call reset() on the long-window instance; the remaining three shall be untouched.
7. The all-time menu entry shall call reset() on the all-time instance; the remaining three shall be untouched.
8. The 'Reset All' menu entry shall call reset() on all four instances.
9. Menu entry labels and tooltip window labels shall derive from one pure formatter over the configured duration: whole hours as 'Nh', whole minutes as 'Nm', else 'Ns', and window None as 'All-time'.
10. Hovering the gauge shall show a tooltip identifying each window as '<window label> — <color name>', using the pure formatter and aesthetic doc color names (cyan, orange, magenta, coral red).
11. Render-tier tests shall assert the composed image produced end-to-end through the real renderer, detecting presence/absence of needles by classifying sampled pixels against the aesthetic doc's palette rows.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Hardcode tooltip text | Simple | Fails when config changes | **Rejected** |
| Dynamic tooltip formatting | Truthful to config | Slightly more complex | **Selected** |

**Rationale:** The specification mandates truthful labeling matching the active configuration (e.g., a 90s config must label as 90s, not 1m). Dynamic pure formatters satisfy this requirement while remaining testable.
