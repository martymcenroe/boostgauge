### 2.5 Logic Flow (Pseudocode)

```
1. ON Initialization:
   - Read config windows.
   - Construct Telltale(short), Telltale(medium), Telltale(long), Telltale(None).
2. ON Update(timestamp, value):
   - For each instance: instance.update(timestamp, value).
3. ON Refresh:
   - Call get_peaks() -> returns tuple of 4 current_peak() values.
   - Pass tuple directly to renderer.
4. ON Hover (Tooltip):
   - Call get_tooltip_text() -> formats label per window and appends ' — <color name>'.
5. ON Menu Action (Reset):
   - Match target identifier and call reset() on the corresponding instance(s).
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/telltale_wiring.py`
* **Pattern:** Manager / Facade
* **Key Decisions:** Extracted integration logic into a pure Python class (`TelltaleManager`). This ensures the app-layer wiring is decoupled from `tkinter`, enabling full unit testability without instantiating `tkinter.Tk()` in tests, adhering perfectly to test strategy Option C.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Menu & Tooltip Formatting | Hardcode vs Dynamic | Dynamic | Must reflect true configured duration; hardcoded strings would drift from configuration. |
| Test Tiers | Mocked Tkinter vs Pure Logic | Pure Logic | Option C forbids Tkinter in tests; purely functional handlers can be tested fully offline. |

**Architectural Constraints:**
- Must integrate with existing `#332` renderer.
- Must read configuration from `#7` `TelltaleWindows`.
- Cannot instantiate GUI elements in unit tests.

## 3. Requirements

1. The app shall instantiate four `Telltale` instances: three with durations read from `telltale_windows.short`, `telltale_windows.medium`, `telltale_windows.long`, and one with window `None` for all-time.
2. The app shall feed every collector sample to all four instances via `Telltale.update(timestamp, value)`, each instance receiving the same `timestamp` and `value` for every sample.
3. Every refresh shall pass all four `current_peak()` values to the renderer as the four-slot telltales argument; a `None` peak reaches the renderer as `None` in its slot.
4. The short-window menu entry shall call `reset()` on the short-window instance, leaving the remaining three untouched.
5. The medium-window menu entry shall call `reset()` on the medium-window instance, leaving the remaining three untouched.
6. The long-window menu entry shall call `reset()` on the long-window instance, leaving the remaining three untouched.
7. The all-time menu entry shall call `reset()` on the all-time instance, leaving the remaining three untouched.
8. The 'Reset All' menu entry shall call `reset()` on all four instances.
9. Menu entry labels and tooltip lines shall derive from one pure formatter over the configured duration: a whole number of hours renders 'Nh', else whole minutes 'Nm', else 'Ns'; the all-time instance renders 'All-time'.
10. Hovering the gauge shall show a tooltip identifying each window, one line per window in the form '<window label> — <color name>', using the aesthetic doc's color names (cyan, orange, magenta, coral red) and verified against non-default configurations.
11. Render-tier tests shall assert the composed image produced end-to-end through the real renderer via pixel classification against the aesthetic doc's palette rows (cyan `#3BD7F0`, orange `#FF9A2E`, magenta `#D45BE8`, coral red `#FF6E7A`) to establish needle presence and absence, pinned by a self-generated baseline.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Mix wiring into `gauge.py` | Consolidates GUI logic | Violates test strategy Option C by requiring Tkinter mocking | **Rejected** |
| Pure `TelltaleManager` | Fully unit testable without Tkinter | Small architectural indirection | **Selected** |

**Rationale:** Option C of the test strategy strictly dictates that `tkinter.Tk()` is never instantiated in tests. A pure logic module provides absolute testing safety and decouples data flow from GUI execution.
