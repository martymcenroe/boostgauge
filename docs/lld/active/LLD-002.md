### 2.5 Logic Flow (Pseudocode)

```
// On Gauge Refresh Tick
1. Receive (timestamp, value) from Collector
2. TelltaleGroup.update(timestamp, value) iterates over all 4 Telltales
3. peaks = TelltaleGroup.current_peaks()
4. Call render(value, peaks, size, ...)

// On Formatter Call
1. IF seconds is None THEN return "All-time"
2. IF seconds modulo 3600 == 0 THEN return (seconds / 3600) + "h"
3. IF seconds modulo 60 == 0 THEN return (seconds / 60) + "m"
4. ELSE return seconds + "s"
```

### 2.6 Technical Approach
* **Module:** `src/boostgauge/telltale_group.py`
* **Pattern:** Facade / Pure Logic Separation
* **Key Decisions:** Keeping all integration, fan-out, and formatting logic in `telltale_group.py` prevents Tkinter GUI contamination of the core data rules. `app.py` simply binds right-click menu commands to the group's reset methods.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Label formatting | Hardcoded strings vs Dynamic formatter | Dynamic formatter | Ensures non-default config values perfectly reflect reality (e.g., "90s") across both menus and tooltips without drift. |
| Test rendering | Mock canvas vs Composed PIL Image | Composed PIL Image | Mandated by Option C test strategy; testing through `stingray.py` ensures the real composed result is validated against the color palette. |

**Architectural Constraints:**
- Logic must remain pure and free from `tkinter.Tk()` dependencies for unit tier.
- Render-tier tests must rely on #332's exact drawing rules and never re-verify visual logic in isolation.

## 3. Requirements

1. The app shall instantiate four Telltale instances: three with durations read from `telltale_windows.short`, `telltale_windows.medium`, `telltale_windows.long`, and one with window `None` for all-time.
2. The app shall feed every collector sample to all four instances via `Telltale.update(timestamp, value)`, each instance receiving the exact same `timestamp` and `value`.
3. The app shall pass all four `current_peak()` values to the renderer as the four-slot telltales argument on every refresh; a `None` peak reaches the renderer as `None`.
4. The short-window menu entry shall call `reset()` on the short-window instance; the remaining three are untouched.
5. The medium-window menu entry shall call `reset()` on the medium-window instance; the remaining three are untouched.
6. The long-window menu entry shall call `reset()` on the long-window instance; the remaining three are untouched.
7. The all-time menu entry shall call `reset()` on the all-time instance; the remaining three are untouched.
8. The 'Reset All' menu entry shall call `reset()` on all four instances.
9. Menu entry labels shall derive from one pure formatter over the configured duration: a whole number of hours renders 'Nh', else whole minutes 'Nm', else 'Ns'; the all-time instance renders 'All-time', prefixed with 'Reset ' for the menu.
10. Hovering the gauge shall show a tooltip identifying each window, one line per window in the form '<window label> — <color name>', where the color names are cyan, orange, magenta, coral red, utilizing the same pure formatter for the window label.
11. Render-tier tests shall assert the composed image produced end-to-end through the real renderer (synthetic streams), with presence and absence established baseline-independently by classifying sampled pixels against the aesthetic doc's palette rows.
