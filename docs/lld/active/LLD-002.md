### 2.5 Logic Flow (Pseudocode)

```
1. Initialize Telltale instances using config durations
2. On collector sample update:
   - Call update(timestamp, value) on all four instances with exact same args
3. On render refresh:
   - Collect current_peak() from all four instances
   - If the all-time peak is greater than the previously recorded all-time peak, emit a debug log and update the recorded peak
   - Pass the 4-slot structure containing peaks and None values to the renderer
4. On context menu action:
   - Dispatch reset() exclusively to the corresponding instance(s)
5. On UI hover:
   - Display tooltip string built via pure formatter logic
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/gauge.py`
* **Pattern:** Dependency Injection for renderer integration
* **Key Decisions:** UI formatting and routing logic are extracted to pure functions. This enables testing the entire feature natively using `tkinter` bindings without instantiating `tkinter.Tk()`, adhering perfectly to Option C. Trace logging will be emitted when the all-time peak increases to improve observability. Configuration hot-reloading for `telltale_windows` is not supported (changes wait for the next launch per ruling #294), avoiding the need for a runtime re-initialization hook.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Peak rendering control | Filtering `None` peaks at wiring layer vs. passing through | Passing through unmodified | Needle-drawing rules (presence, absence, opacity) strictly belong to #332's renderer |
| Menu/Hover testing | Instantiating `Tk()` vs. extracting pure logic | Extracting pure logic | Banned by Test Strategy Option C |
| Z-order tests | Asserting via visual tests vs. deferring to aesthetic doc | Deferring to aesthetic doc | Operator ruled in #232 that z-order is a spec convention, not a tested criterion |
| Runtime config changes to `telltale_windows` | Re-initialize Telltales on change vs. Wait for next launch | Wait for next launch | Per ruling #294 and `config.py`, only `thresholds` are applied mid-session; `telltale_windows` changes are applied on restart. No re-initialization hook needed. |

**Architectural Constraints:**
- Must exclusively use #41's `Telltale` logic without duplicating peak arithmetic.
- Cannot instantiate `tkinter.Tk()` inside any test.

## 3. Requirements

1. The app shall instantiate four `Telltale` instances, three populated from config `telltale_windows.short`, `telltale_windows.medium`, `telltale_windows.long`, and one with window `None` for all-time.
2. The app shall feed every collector sample to all four instances via `update(timestamp, value)`, passing identical timestamps and values to each.
3. The app shall pass all four `current_peak()` values to the renderer on every refresh as a four-slot structure, passing `None` through unmodified.
4. The short-window menu entry shall call `reset()` exclusively on the short-window instance.
5. The medium-window menu entry shall call `reset()` exclusively on the medium-window instance.
6. The long-window menu entry shall call `reset()` exclusively on the long-window instance.
7. The all-time menu entry shall call `reset()` exclusively on the all-time instance.
8. The 'Reset All' menu entry shall call `reset()` on all four instances.
9. Menu entry labels shall derive dynamically from a pure formatter over the configured duration, rendering whole hours as 'Nh', whole minutes as 'Nm', and else 'Ns'.
10. The hover tooltip shall identify each window using the format '<window label> — <color name>' (cyan, orange, magenta, coral red), generated by a pure function without `tkinter`.
11. The composed image shall be tested end-to-end through the real renderer to verify needle presence and absence via pixel classification against the aesthetic doc's palette.
12. The app shall emit a debug log when a new all-time peak is established for observability and diagnostic tracing.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Filter `None` at wiring layer | Avoids passing invalid values to renderer | Violates strict #332 drawing ownership | **Rejected** |
| Hardcode default labels | Simpler implementation | Fails when user overrides config | **Rejected** |

**Rationale:** The rendering boundary must remain pure per issue scope guards. Label logic must be completely dynamic to support custom config horizons reliably.
