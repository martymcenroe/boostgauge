### 2.5 Logic Flow (Pseudocode)

```
1. Receive render() call with value, telltales, size, config.
2. Resolve skin from config (defaults to 'stingray').
3. Delegate to render_stingray(value, telltales, size).
4. In render_stingray:
   a. Check if background for given size is cached; if not, call _render_background().
   b. Copy background image as base layer.
   c. Iterate over telltales:
      - Calculate opacity based on proximity distance to main needle value (fades at 3 units to 100% at 2 units).
      - Draw telltale needles at their respective peak angles with the determined opacity.
   d. Draw main needle at the `value` angle in candy-apple red.
5. Return the fully composited PIL.Image.
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/gauge.py` and `src/boostgauge/skins/stingray.py`
* **Pattern:** Strategy Pattern (Delegation)
* **Key Decisions:** Implement as a pure function returning a `PIL.Image` per the Option C testing strategy, ensuring absolutely no `tkinter` imports exist in the rendering stack. The aesthetic specification and baseline verification will dictate drawing coordinates.

## 3. Requirements

1. The renderer must provide a pure function `render(value, telltales, size, config)` returning a `PIL.Image` with no hidden state, no side effects, and no `tkinter` imports.
2. A static gauge image at value=0 and telltales=None must match the canonical reference image (`images/aesthetic-v1-stingray-canonical.jpg`) within the visual-regression tolerance.
3. The renderer must be deterministic: two function calls with identical inputs must produce byte-identical `PIL.Image` outputs.
4. At value=100 and no telltales, the main needle must be located at the rightmost arc position with the rest of the gauge visually unchanged from value=0.
5. Telltales must be visible with a translucent baseline, fading to full (100%) opacity at 2 scale units of the main needle, and fading from baseline at 3 scale units. Exact coincidence occlusion is accepted by design.
6. At value=75, the main needle tip (candy-apple red) must be visually distinct from the brick-red redline band occupying the outer 80–100% of the dial radius from 60–100.
7. Visual regression tests must systematically cover checkpoints (value=0, 50, 75, 80, 100), near-overlap telltales, far telltales, and post-reset scenarios.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Vector/SVG backend | Infinite resolution scaling natively | Requires external rasterization libraries; harder to test as pixel-perfect | **Rejected** |
| Native PIL Drawing | Zero additional dependencies, anti-aliasing handled via Pillow | Manual trigonometric math required for arcs and polygon rotations | **Selected** |

**Rationale:** Native Pillow drawing keeps the dependency footprint minimal and directly aligns with the Option C test strategy requirements out of the box.

### 7.2 Safety

| Concern | Mitigation | Status |
|---------|------------|--------|
| Image allocation memory leak | Do not retain persistent references to returned PIL.Images in renderer; leave lifecycle to caller GC | Addressed |

**Fail Mode:** Fail Closed - If structurally invalid sizes or bad configuration schemas are requested, raise standard Python exceptions (`ValueError`) early so the caller can abort the UI frame.

**Recovery Strategy:** Caller handles exceptions during rendering and simply skips the frame update.

## 8. Performance & Cost Considerations

### 8.1 Performance

| Metric | Budget | Approach |
|--------|--------|----------|
| Latency | < 5ms | Use `_render_background()` to pre-calculate and cache the static housing/dial drawing. |
| Memory | < 5MB per tick | Re-use background image objects via shallow copying (`Image.copy()`) and rely on immediate Python garbage collection of the returned `PIL.Image`. |
| API Calls | 0 | Pure local computation. |

**Bottlenecks:** Math computations for anti-aliased polygons and redline arcs on a pixel grid.
