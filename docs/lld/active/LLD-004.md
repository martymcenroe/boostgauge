### 2.5 Logic Flow (Pseudocode)

```
1. `collect()` triggered per tick by background thread.
2. Read `psutil.virtual_memory().percent`.
3. Call `_sweep()` (single `NtQuerySystemInformation` Win32 API call).
4. Iterate once over returned structure:
   - Increment `process_count`.
   - Add `HandleCount` to `handle_count`.
   - If image name is "conhost.exe" or "OpenConsole.exe", increment `conpty_count`.
   - If image name is Python interpreter, call `_read_cmdline_safe(pid)`.
     - If matches "unleashed-c-*.py", increment `unleashed_sessions`.
     - Handle AccessDenied/NoSuchProcess gracefully by skipping.
5. Compute composite metric using `_normalize()` max algorithm.
6. Assemble and return `SystemSnapshot`.
7. Thread puts snapshot in thread-safe state container.
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/collectors/windows.py`
* **Pattern:** Background Poller & Abstract Factory (Collector per OS)
* **Key Decisions:** Used `ctypes` directly against `NtQuerySystemInformation(SystemProcessInformation)` to satisfy the 2.2 ms single-sweep requirement. All process-derived metrics are computed during this single loop. The `psutil` library is retained strictly for the non-enumerating `virtual_memory()` call and the per-row `Process(pid).cmdline()` reads on identified Python rows.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Sweep Mechanism | `psutil.process_iter`, `NtQuerySystemInformation` | `NtQuerySystemInformation` | ADR 0001: `process_iter` takes 422ms (21% CPU), Win32 API takes 2.2ms (0.11% CPU). |
| Metric Normalization | Average, Max | Max | A single saturated resource (e.g., 95% ConPTY) means the system is choking; averaging hides this. |
| Concurrency | `asyncio`, Background Thread | Background Thread | Metrics collection is blocking (Win32 syscalls/ctypes). A separate thread safely isolates GUI from collection pauses. |

**Architectural Constraints:**
- The sweep MUST NOT invoke `psutil.process_iter`, `psutil.pids()`, `Get-Process`, or WMI.
- `cmdline` must only be read on identified Python processes, never broadly.

## 3. Requirements

1. Collector returns accurate ConPTY count — the sweep's console-host count equals psutil's `process_iter` console-host count on the running machine (±1) utilizing up to three back-to-back pair checks.
2. Collector returns accurate process count (±1 against psutil) and handle count (within 1% of psutil's `num_handles` sum) utilizing up to three back-to-back pair checks.
3. Collector returns memory % as exactly one direct `psutil.virtual_memory().percent` read taken on the tick, without cross-checking against a live read.
4. Unleashed session detection filters where the sweep row's process `name` is a Python interpreter (case-insensitive) AND its per-row `cmdline` matches `unleashed-c-*.py`.
5. Polling is non-blocking and executes in a background thread at the configured interval.
6. Collector gracefully handles permission errors (e.g. `AccessDenied` or `NoSuchProcess`) during per-row `cmdline` reads without failing the tick.
7. All process-derived metrics come from a single `NtQuerySystemInformation` sweep of the process table per tick.
8. The whole tick (`collect()` call) consumes < 1% CPU overhead at 2s polling interval (mean `process_time` < 20 ms over 8 ticks, discarding the first).
9. Composite metric implements the normalized-max algorithm and surfaces the highest metric's name in the `driver` field.
10. Source code must not contain independent OS queries like `psutil.pids`, `psutil.process_iter`, or `Get-Process` (source-level pin).

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| `psutil.process_iter` | Easy to write, cross-platform | 422 ms cost violates < 1% overhead limit by opening every process to read handles. | **Rejected** |
| WMI / PowerShell | Built-in Windows tooling | Spawns processes per tick; historically caused system hangs. | **Rejected** |
| `NtQuerySystemInformation` | 2.2 ms cost, single sweep | Requires `ctypes` parsing of undocumented Windows structures. | **Selected** |

**Rationale:** The `< 1%` CPU requirement and ADR 0001 dictate `NtQuerySystemInformation` as the only viable mechanism for Windows.

## Reviewer Suggestions

*Non-blocking recommendations from the reviewer.*

- **Buffer Size Bound:** When handling `STATUS_INFO_LENGTH_MISMATCH` for the `NtQuerySystemInformation` buffer reallocation, consider adding a hard upper limit (e.g., 5MB or 10MB) to prevent pathological memory exhaustion if the OS continuously reports invalid required lengths.
- **Logging Clarity:** While the Safety section mentions "log, and yield safe zeros/last values", consider explicitly instantiating a module-level logger (e.g., `logger = logging.getLogger(__name__)`) and logging dynamic buffer resizing events or `collect()` latencies at the `DEBUG` level for easier troubleshooting of tick overruns in production.
