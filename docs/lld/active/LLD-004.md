### 2.5 Logic Flow (Pseudocode)

```
1. Initialize WindowsCollector(thresholds, poll_interval)
2. start() spawns _poll_loop in a daemon Thread
3. In _poll_loop (runs every poll_interval seconds):
   a. Call sweep()
      - Call NtQuerySystemInformation(SystemProcessInformation) via ctypes
      - Walk the returned memory block exactly once
      - Track:
        - process_count = total rows
        - handle_count = sum(HandleCount)
        - conpty_count = rows where name in ("conhost.exe", "OpenConsole.exe")
        - unleashed_sessions = For rows where name is python interpreter, read cmdline via psutil. If matches "unleashed-c-*.py", add 1. Skip on AccessDenied/NoSuchProcess.
      - memory_percent = psutil.virtual_memory().percent
   b. Compute composite_value and driver via normalized-max algorithm
   c. Put SystemSnapshot in Queue
4. Sleep until next poll interval
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/collectors/windows.py`
* **Pattern:** Background Thread Producer + Abstract Base Class
* **Key Decisions:** Strict adherence to ADR 0001 single-sweep mandate. `NtQuerySystemInformation` is called exactly once per tick via `ctypes` directly. `psutil` is invoked ONLY for `virtual_memory()` and for the specific `cmdline` property of identified Python PIDs. The `composite_value` uses the normalized-max algorithm across metrics.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Windows API Sweep | psutil `process_iter`, WMI, PowerShell, `NtQuerySystemInformation` | `NtQuerySystemInformation` | ADR 0001 mandate. `psutil` opens every process for handles (422ms). `NtQuery` takes ~2.2ms and provides name, pid, and handles without opening processes. |
| Threading | Asyncio, Threading | Threading | GUI uses tkinter which relies on a main loop. Polling block is native/ctypes; a background Thread with a thread-safe Queue avoids blocking the UI and keeps polling precise. |

**Architectural Constraints:**
- Must conform strictly to `docs/adrs/0001-single-sweep-collection.md` (no secondary walks or independent process OS queries).
- Must NEVER use `Get-Process`, `psutil.pids()`, or `psutil.process_iter()` for counting rows.

## 3. Requirements

1. The collector's ConPTY count MUST equal `psutil`'s `process_iter` console-host count on the running machine (±1).
2. The collector's process count MUST equal `psutil`'s row count (±1) and handle count MUST be within 1% of `psutil`'s `num_handles` sum.
3. The unleashed session count MUST increment only when a sweep row's `name` is a Python interpreter AND its `cmdline` read via `psutil` (for that row only) matches the `unleashed-c-*.py` signature.
4. Polling MUST be non-blocking, run in a background thread with a configurable interval (default 2s), and push results to a thread-safe queue.
5. The sweep MUST gracefully handle permission errors (`AccessDenied`, `NoSuchProcess`) without retrying the query.
6. All process-derived metrics (process count, ConPTY count, handle count, unleashed sessions) MUST come from exactly ONE `NtQuerySystemInformation` call per tick.
7. The sweep's mean `process_time` over 8 ticks MUST be < 20 ms.
8. The `SystemSnapshot` MUST include `composite_value` (0-100) and `driver` computed via the normalized-max algorithm.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| `psutil.process_iter` | Clean API, cross-platform | 422ms CPU per tick due to opening processes for handles | **Rejected** |
| WMI | Built-in Windows query tool | Caused system hangs; spawns subprocesses | **Rejected** |
| `NtQuerySystemInformation` | 2.2ms native sweep, no handles opened | Requires ctypes parsing of undocumented struct | **Selected** |

**Rationale:** The `NtQuerySystemInformation` approach is the ONLY way to meet the `< 1% CPU` overhead acceptance criterion required by Issue #4, as formalized in ADR 0001.

### 7.2 Safety

| Concern | Mitigation | Status |
|---------|------------|--------|
| Zombie Thread on Exit | Background thread set as `daemon=True` and checks a `_stop_event` flag | Addressed |
| AccessDenied exceptions on `cmdline` | Try/except block catching `psutil.AccessDenied` and `psutil.NoSuchProcess` during per-row reads, skipping the row | Addressed |

**Fail Mode:** Fail Open - The collector skips rows it cannot inspect and continues polling.
**Recovery Strategy:** Re-polls on the next tick; temporary OS access glitches only affect a single 2s snapshot.

## 11. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Ctypes structure misalignment on x64 vs x86 | High | Low | Explicitly define `SYSTEM_PROCESS_INFORMATION` with fixed sizes for x64. Target env is 64-bit Windows 11. Implemented in `WindowsCollector.sweep`. |
| Memory leak in `NtQuerySystemInformation` buffer | High | Low | Use `ctypes.create_string_buffer` to ensure Python garbage collects the buffer per sweep tick. Implemented in `WindowsCollector.sweep`. |
| Unresponsive `psutil` cmdline call on frozen process | Medium | Low | `psutil` handles its own native timeouts, but background thread isolation prevents gauge UI freeze. Implemented via `DataCollector._poll_loop`. |
