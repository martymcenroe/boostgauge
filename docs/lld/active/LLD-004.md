### 2.5 Logic Flow (Pseudocode)

```
1. Wait for poll_interval in _poll_loop
2. Initialize counters: conpty=0, process=0, handles=0, unleashed=0
3. Sweep: For each proc in psutil.process_iter(attrs=["name", "num_handles", "cmdline"]):
   - IF NoSuchProcess or AccessDenied exception occurs: continue
   - process += 1
   - name = proc.info["name"].lower()
   - IF name in ("conhost.exe", "openconsole.exe"): conpty += 1
   - IF num_handles exists: handles += num_handles
   - IF name in python_interpreters AND "unleashed-c-" in cmdline: unleashed += 1
4. memory = psutil.virtual_memory().percent
5. Compute composite_value and driver via normalized-max over the 4 resources
6. Emit SystemSnapshot to queue
7. Repeat
```

### 2.6 Technical Approach

* **Module:** `src/boostgauge/collectors/windows.py`
* **Pattern:** Producer-Consumer and Abstract Factory
* **Key Decisions:** Implemented strictly per ADR 0001, deriving ConPTY, process count, handle count, and unleashed session count from one `psutil.process_iter` sweep. Handled exceptions mid-walk to prevent thread crashes. Normalized-max calculation is decoupled into `_normalize()` to determine the driving resource.

### 2.7 Architecture Decisions

| Decision | Options Considered | Choice | Rationale |
|----------|-------------------|--------|-----------|
| Process Enumeration | 1. Single `psutil.process_iter`, 2. Win32 API, 3. WMI/CIM | Single `psutil.process_iter` | Mandated by ADR 0001 to guarantee < 1% CPU overhead. WMI can hang; multiple Win32 calls are too expensive. |
| Background Polling | 1. `threading.Thread`, 2. `multiprocessing`, 3. `asyncio` | `threading.Thread` | GUI uses `tkinter` which blocks the main thread. A background thread with a thread-safe queue provides the simplest non-blocking data feed. |

**Architectural Constraints:**
- The process sweep must be completed in exactly one iteration per tick (ADR 0001).
- Must avoid GUI components in collector tests (`tkinter.Tk()` is prohibited per `0001-test-strategy.md`).

## 3. Requirements

1. The Windows collector MUST derive ConPTY count, process count, handle count, and unleashed session count from a SINGLE `psutil.process_iter(attrs=["name", "num_handles", "cmdline"])` sweep per tick.
2. The memory percentage MUST be measured using `psutil.virtual_memory().percent` outside the sweep.
3. The collector MUST skip any process that raises `psutil.NoSuchProcess` or `psutil.AccessDenied` during the sweep without crashing or retrying.
4. Process count MUST equal the exact number of rows successfully processed in the sweep.
5. ConPTY count MUST be the number of sweep rows where the process name is `conhost.exe` or `openconsole.exe` (case-insensitive).
6. Handle count MUST be the sum of `num_handles` across all successfully read rows in the sweep.
7. Unleashed session count MUST be the number of sweep rows where the process name is a Python interpreter (case-insensitive) AND the `cmdline` matches `unleashed-c-*.py`.
8. The collector MUST run its poll loop in a non-blocking background thread and push `SystemSnapshot` objects to a thread-safe queue.
9. The `SystemSnapshot` MUST calculate its `composite_value` (0-100) and `driver` string using the normalized-max algorithm across ConPTY, memory, processes, and handles.
10. The background polling interval MUST be configurable, defaulting to 2.0 seconds.
11. The collector's CPU overhead MUST be < 1% at a 2.0-second polling interval.

## 4. Alternatives Considered

| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| WMI/CIM | Native, highly detailed metrics | Historically caused system hangs; slow | **Rejected** |
| Direct Win32 API for ConPTY | Zero dependency, highly accurate | Requires a separate process walk, violating ADR 0001 | **Rejected** |
| Separate cadences per metric | Limits overhead of expensive metrics | Unnecessary complexity if a single sweep is used | **Rejected** |

**Rationale:** ADR 0001 strictly dictates the single-sweep methodology to solve overhead problems fundamentally. All alternatives violate this mandate.

## 11. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Process disappearance during sweep crashing thread | High | High | Wrap per-process property reads in try/except blocks catching `psutil.NoSuchProcess` and `psutil.AccessDenied` within `_collect_snapshot`. |
| Excessive CPU usage from process walk | High | Medium | Strictly enforce ADR 0001 (one `psutil.process_iter` per tick) and filter strictly via `attrs` to prevent excess OS queries. |
| Main thread blocking | High | Low | Isolate all polling logic into `_poll_loop` running as a background daemon thread communicating exclusively via `queue.Queue`. |
